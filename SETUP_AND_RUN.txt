================================================================================
RMG BLOCKCHAIN SYSTEM - COMPLETE SETUP & RUN GUIDE
================================================================================

This guide walks through running the entire system locally with Anvil, MongoDB,
Backend, and Frontend.

================================================================================
PREREQUISITE SOFTWARE
================================================================================

1. Node.js & npm (for backend & frontend)
2. Foundry (for smart contract deployment) - https://book.getfoundry.sh/
3. MongoDB Atlas Account (cloud database) - https://www.mongodb.com/cloud/atlas
4. MetaMask Browser Extension (for wallet)

================================================================================
SETUP MONGODB ATLAS (CLOUD DATABASE)
================================================================================

Step 1: Create MongoDB Atlas Account
  1. Go to: https://www.mongodb.com/cloud/atlas
  2. Click "Try Free"
  3. Sign up with email or Google
  4. Create organization and project

Step 2: Create a Cluster
  1. Click "Create Deployment"
  2. Choose "Free" tier (enough for development)
  3. Select cloud provider: AWS/Google Cloud/Azure (any is fine)
  4. Select region (choose closest to you)
  5. Click "Create Cluster"
  6. Wait for cluster to deploy (5-10 minutes)

Step 3: Create Database User
  1. Go to "Security" → "Database Access"
  2. Click "Add New Database User"
  3. Username: (anything, e.g., "rmg-admin")
  4. Password: (strong password, copy it)
  5. Click "Add User"

Step 4: Allow Network Access
  1. Go to "Security" → "Network Access"
  2. Click "Add IP Address"
  3. Click "Allow Access from Anywhere"
  4. Click "Confirm"

Step 5: Get Connection String
  1. Go to "Databases" → Your cluster
  2. Click "Connect"
  3. Choose "Drivers" → "Node.js"
  4. Copy the connection string (looks like):
     mongodb+srv://rmg-admin:PASSWORD@cluster0.xxxxx.mongodb.net/rmg-blockchain?retryWrites=true&w=majority

Step 6: Update Backend .env
  Replace PASSWORD with your actual password in the connection string
  
  Location: backend/.env

  Content:
    PORT=3000
    MONGODB_URI=mongodb+srv://rmg-admin:YOUR_PASSWORD@cluster0.xxxxx.mongodb.net/rmg-blockchain?retryWrites=true&w=majority
    RPC_URL=http://localhost:8545
    CONTRACT_ADDRESS=0x5FbDB2315678afccb333f8a9c92c1ea4c6270fcc
    PRIVATE_KEY=0xac0974bec39a17e36ba4a6b4d238ff944bacb476cac3ee66a56c8b58e0e8c1d5

Replace:
  - YOUR_PASSWORD with your database user password
  - cluster0.xxxxx with your actual cluster ID
  - CONTRACT_ADDRESS with value from deployment
  - PRIVATE_KEY with first account from Anvil startup

💡 IMPORTANT:
  - Atlas handles MongoDB for you automatically
  - No local MongoDB server needed
  - No data directory required
  - Backend will connect to cloud automatically

================================================================================
HOW ROLE DETECTION WORKS
================================================================================

1. User connects MetaMask wallet
2. System gets user's wallet address
3. Compares address with env variables:
   - VITE_CERTIFIER_ADDRESS
   - VITE_SELLER_ADDRESS
   - VITE_BUYER_ADDRESS
   - ... etc ...
4. If match found: role is assigned
5. If no match: "No Role" state
6. Dashboard shows role status indicator

Role Assignment is Automatic:
  - No login/password needed
  - User just connects wallet
  - Role determined by address
  - Different accounts = different roles

To Test Different Roles:
  1. Switch MetaMask accounts
  2. Refresh browser (or wait for auto-detection)
  3. New role applies
  4. Access permissions change

TROUBLESHOOTING
================================================================================

Problem: "Cannot connect to MongoDB"
Solution:
  - Verify MongoDB_URI in backend/.env is correct
  - Check username and password are correct
  - Verify IP address is whitelisted in Atlas (Security → Network Access)
  - Test connection string in MongoDB Compass to verify

Problem: "Cannot connect to Anvil"
Solution:
  - Keep anvil running in Terminal 1
  - Check RPC_URL in backend/.env is http://localhost:8545
  - Verify Anvil terminal shows "Listening on 127.0.0.1:8545"

Problem: "Contract address is blank or 0x0000..."
Solution:
  - Re-run deployment: forge script script/Deploy.s.sol --broadcast
  - Copy correct address to backend/.env and frontend/.env.local
  - Restart backend and frontend

Problem: "MetaMask won't connect"
Solution:
  - Verify Anvil network is added to MetaMask
  - Switch to Anvil network before connecting
  - Check Chain ID is exactly 31337
  - Try disconnecting and reconnecting wallet

Problem: "Role shows as 'No Role'" even when connected
Solution:
  - Check your wallet address matches a VITE_*_ADDRESS
  - Verify frontend/.env.local has correct addresses
  - Check addresses are lowercase in env
  - Refresh browser
  - Hard reload (Ctrl+Shift+R)

Problem: Frontend says "Access Denied" on all panels
Solution:
  - Your wallet address doesn't match any role address
  - Switch to a different Anvil account in MetaMask
  - Or update VITE_*_ADDRESS values with your addresses

Problem: "Port 3000 already in use"
Solution:
  - Kill process on port 3000: Get-Process -Name node | Stop-Process
  - Or change PORT in backend/.env and restart

Problem: "Port 5173 already in use"
Solution:
  - Another frontend dev server is running
  - Kill it or wait for it to finish
  - Or change port in vite.config.ts

Problem: "npm install fails"
Solution:
  - Delete node_modules folder
  - Delete package-lock.json
  - Run: npm install again
  - Ensure Node.js version >= 16
