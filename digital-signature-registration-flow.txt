# Digital Signature Registration Flow (Backend-Relayer Pattern)

## 1. User Registration (Frontend)
- User fills out the registration form (e.g., name, license, contact).
- Frontend creates a message from the form data (e.g., JSON.stringify(formData)).
- Frontend asks MetaMask to sign the message (signMessage).
- MetaMask prompts the user to sign (no gas, no transaction).
- Frontend receives the digital signature.
- Frontend sends the following to the backend:
  - data: the original form data
  - signature: the digital signature from MetaMask
  - userAddress: the user's wallet address

## 2. Backend Verification
- Backend receives { data, signature, userAddress }.
- Backend reconstructs the message (must match what was signed).
- Backend uses ethers.verifyMessage(message, signature) to recover the address that signed the message.
- Backend compares the recovered address to userAddress:
  - If they match: signature is valid, user approved the data.
  - If not: reject the request (invalid signature or tampered data).

## 3. Backend Contract Execution
- Backend hashes the data (e.g., ethers.keccak256(ethers.toUtf8Bytes(message))) for on-chain reference.
- Backend prepares the contract call (e.g., registrationseller(name, tinid, number)).
- Backend signs and sends the transaction using its own private key (from .env, NOT the user's key).
- Backend pays the gas for the transaction.
- Contract function executes on-chain, state is updated.
- Backend waits for transaction confirmation.

## 4. Audit Trail & Storage
- Backend stores in the database:
  - userAddress
  - data
  - signature
  - dataHash
  - txHash
  - blockNumber
- This provides a full audit trail for compliance and security.

## 5. Security Notes
- User's private key is NEVER shared with backend or anyone else.
- Digital signature only proves user intent; it cannot be used to send transactions as the user.
- Backend controls contract execution, can validate and filter requests before sending to blockchain.
- If you want the user to pay gas and call the contract directly, use sendTransaction in the frontend (not this flow).

## Summary Table
| Step                | Who signs?         | Who pays gas? | On-chain? | Purpose                       |
|---------------------|--------------------|---------------|-----------|-------------------------------|
| signMessage         | User (MetaMask)    | No one        | No        | Prove user intent             |
| Backend tx          | Backend            | Backend       | Yes       | Execute contract, update state|

---
This flow ensures secure, verifiable, and auditable user registration using digital signatures and backend-controlled contract execution.
