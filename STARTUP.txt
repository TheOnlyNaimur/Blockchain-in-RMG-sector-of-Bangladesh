================================================================================
                    BLOCKCHAIN RMG STARTUP GUIDE
================================================================================

WORKFLOW OVERVIEW:
-------------------

1. COMPILE SOLIDITY CODE
   Command: forge build --force
   Location: Root directory
   Output: out/MyContract.sol/MyContract.json (compiled ABI)
   Note: Run this whenever you modify Solidity code in src/

2. COPY ABI TO BACKEND
   Command (bash): cp out/MyContract.sol/MyContract.json backend/abi/MyContract.json
   Why: Backend needs the contract interface to interact with deployed contract
   IMPORTANT: Do this after EVERY forge build if you modify the contract

3. DEPLOY CONTRACTS TO ANVIL
   Script: script/Deploy.s.sol
   Command: forge script script/Deploy.s.sol --rpc-url http://localhost:8545 --broadcast
   What it does:
     - Deploys MockUSDT contract
     - Deploys MyContract with 6 parameters
     - Mints USDT for testing
   Note: Anvil must be running (see step 5 below)

4. START BACKEND SERVER
   Terminal 1:
     cd backend
     npm start
   Runs on: http://localhost:5000 (or configured PORT)
   Dependencies: Node.js, npm packages installed

5. START LOCAL BLOCKCHAIN (ANVIL)
   Terminal 2:
     anvil
   Chain ID: 31337
   RPC URL: http://localhost:8545
   Default accounts: 10 test accounts with ETH

6. START FRONTEND
   Terminal 3:
     cd frontend
     npm run dev
   Runs on: http://localhost:5173
   Access: http://localhost:5173

WHEN TO RUN EACH COMMAND:
================================================================================

forge build --force
  → When you modify Solidity files (src/MyContract.sol, etc)
  → ALWAYS copy ABI after this

Copy ABI
  → Immediately after forge build
  → When contract interface changes
  → Path: out/MyContract.sol/MyContract.json → backend/abi/MyContract.json

Deploy
  → After restarting Anvil
  → When you need fresh contract instances
  → After major contract logic changes

npm start (backend)
  → Once per session
  → Restarts if you modify backend code

npm run dev (frontend)
  → Once per session
  → Auto-reloads on file changes

================================================================================
RESTARTING ANVIL - CRITICAL CONCEPT:
================================================================================

WHAT HAPPENS WHEN YOU CLOSE AND RESTART ANVIL?

Anvil stores everything in MEMORY - it is NOT persistent.

When you close Anvil:
  ❌ All deployed contracts are DELETED
  ❌ All contract state is ERASED
  ❌ All account balances RESET
  ❌ You get a completely fresh blockchain

WORKFLOW AFTER RESTARTING ANVIL:

  Terminal 1: Start fresh Anvil
    anvil

  Terminal 2: Redeploy contracts
    forge script script/Deploy.s.sol --rpc-url http://localhost:8545 --broadcast

  This redeploys:
    ✅ MockUSDT contract
    ✅ MyContract with 6 parameters
    ✅ USDT minting

DO YOU NEED forge build AGAIN?

  NO - Unless you modified Solidity code:
    - No code changes → Skip forge build, just redeploy
    - Modified code → forge build --force → copy ABI → redeploy

COMPARISON TABLE:

Action                           | forge build? | copy ABI? | redeploy?
---------------------------------|--------------|----------|----------
Restart Anvil (no code changes)  | ❌ No        | ❌ No    | ✅ YES
Modify Solidity code             | ✅ YES       | ✅ YES   | ✅ YES
Restart backend/frontend         | ❌ No        | ❌ No    | ❌ No
Modify backend code              | ❌ No        | ❌ No    | ❌ No

KEY TAKEAWAY:
  When Anvil restarts → Always redeploy contracts
  No code changes → Skip forge build, just redeploy
  Code changes → Full cycle: build + copy + deploy

================================================================================
IMPORTANT NOTES:
================================================================================

1. ABI COPY IS CRITICAL
   Without copying ABI to backend/abi/MyContract.json:
   - Backend cannot call contract functions
   - Frontend cannot interact with contract
   
2. ANVIL PERSISTENCE
   Anvil resets when you restart it
   → You lose all deployed contracts
   → Solution: Always redeploy after restarting Anvil

3. DEPLOYMENT ADDRESSES
   After deployment, note the contract addresses:
   - MockUSDT: 0x... (USDT token)
   - MyContract: 0x... (main contract)
   These are used in environment files

4. FRONTEND .env
   Location: frontend/.env
   Must contain deployed contract addresses and role addresses
   Update after each deployment if addresses change

5. BACKEND .env
   Location: backend/.env
   Must contain:
     - MONGODB_URI connection string
     - Deployed contract addresses
     - Private keys for role testing (if applicable)

================================================================================
TROUBLESHOOTING:
================================================================================

Backend cannot call contract?
  → Check: backend/abi/MyContract.json exists and is up-to-date
  → Run: cp out/MyContract.sol/MyContract.json backend/abi/MyContract.json

Contract deployment fails?
  → Check: Anvil is running (anvil command in separate terminal)
  → Check: RPC URL is correct (http://localhost:8545)
  → Check: forge build succeeded (no compilation errors)

Frontend cannot connect?
  → Check: Backend is running (npm start in backend)
  → Check: VITE_API_URL in frontend/.env is correct
  → Check: Port 5000 is available for backend

Anvil fork_error or version mismatch?
  → Update: forge install
  → Rebuild: forge build --force
